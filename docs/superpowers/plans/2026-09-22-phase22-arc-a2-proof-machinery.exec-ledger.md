> **F2.I-NEG -- RULING: NONE of (a)/(b)/(c). Segments are defined by the ORDERED endpoints, and a segment of zero or negative length is NOT EMITTED. When `record_at >= barrier_armed_at`: `writer_absence_only` = [fire_hi, barrier_armed_at); NO `match_only` segment exists; `covered` = [barrier_armed_at, read_at]; `record_at` stays in the endpoints with a recorded `record_position = 'inside_coverage'` (else `'before_barrier'`). The verdict is unchanged (criteria 1-4 as ruled; gaps never decide). Negative seconds never appear anywhere; every emitted segment has `seconds > 0`.**
> Reason. The `match_only` span exists to name the period in which the ONLY thing standing between the frozen values and a silent change was a net-change check -- the operator's record with no barrier behind it. When the record is authored after the barrier armed, that period never existed: from `barrier_armed_at` the row is immutable by trigger, and the record merely confirms values already under coverage. So the evidence is not weaker but STRONGER (the uncovered window is shorter and purely writer-absence), which is why (c) REFUSE is wrong -- it would refuse the better evidence. (a) clamp emits a zero-length `match_only`, which ASSERTS that a match-only period existed for 0 s: a misstatement in the row's own voice, and the exact shape the "existence is not completeness" family warns about. (b) a new kind `match_after_barrier` names a span whose coverage is the barrier's, not the match's -- merging two evidence kinds under one label. None of the three states what actually happened; the ordered-endpoint rule does, and it is the rule the interval was built on (I-1: "segments" are what the endpoints induce, not a fixed roster of four).
> Consequences for the encoding, stated so they are not re-derived: (i) the SQL assertion "the four segment kinds are present in order" becomes "the emitted kinds appear in the canonical order `fire, writer_absence_only, match_only, covered` with `match_only` OPTIONAL, and `match_only` present IFF the blob's `record_at.utc < barrier_armed_at.utc`" -- if SQL cannot compare the `utc` fields (R8-03: it binds raw only) then the presence rule is a SERVICE check with a named `-- TIER2-PREDICATE` twin asserting only the ORDER, and the IFF is pinned in Python (A2-60's closure covers it); (ii) `uncovered_window_prose` names the case: "writer_absence_only <d> days (<fire_hi> to <barrier_armed_at>); covered from <barrier_armed_at>; record authored inside coverage at <record_at>"; (iii) `VERDICT_BEARING_KEYS` gains `record_position`; (iv) the writer_absence_only segment's END is `min(record_at, barrier_armed_at)` in both cases -- one formula, no branch.
> Discriminators (both on the trade-25 world with the barrier time moved, nothing else): record = barrier_armed_at + 1 s -> segments exactly `[fire, writer_absence_only, covered]`, `record_position = 'inside_coverage'`, prose contains "inside coverage", every `seconds > 0`; record = barrier_armed_at - 1 s -> `match_only` present with `seconds == 1`. Boundary twin: record == barrier_armed_at -> NO `match_only` (empty is not emitted), `inside_coverage`. A literal impl emits negative seconds on the first case and fails; a clamp impl emits `match_only 0` and fails; a refuse impl refuses the first case and fails.
